## BUG-2957 · Emby/Jellyfin/Plex 与在线视频源上没有波形对轴、自动对轴与语音重定时
- **报告**：2026-10-05（用户：「波形对轴跑哪了，emby没有竟然」）
- **真实性**：✅ 真 bug（功能缺口，非回归）。三个入口共用的同步判据 `_canResolveSubtitleTimingAudio`（`fushi/lib/src/pages/implementations/video_fushi/subtitle.part.dart`，修前 :3021）只认「本机视频文件」或「互联 host 裁整集音轨」；音源解析 `_resolveSubtitleTimingAudio` 同样只有这两条分支。Emby / Jellyfin / Plex、在线视频源（Aniyomi 扩展 / 粘贴的流）与 YouTube 播放时 `videoPath` 为空、也不是互联后端，入口整个不挂（快速设置面板无「波形对轴」，Shift+A 只提示「本设备无法生成波形」，自动对轴 / 语音模型生成与重定时字幕同样缺席）。自 `a8d8147ccc`（五端波形对轴）起门条件就是 `videoPath.isNotEmpty`，`809961ed95`（BUG-2728）只补了互联 host 一条。底层 `extractAudioEnergyEnvelope` 要求本地文件，网络流没有任何一步把它变成本地文件。
- **[x] ① 已修复** — 音源解析补网络流分支：本机 ffmpeg 经**制卡同一条取流路径**（新 `_routeFfmpegPlaybackInput`：媒体服务器 / 在线源走本机中继，BUG-2692；YouTube 直读；制卡也改调它，改道判断全页只此一处）抽出当前音轨（YouTube 分离流取 audio-only 那一路）落到本机临时文件，交给既有波形 / 互相关 / 设备端转录。互联视频仍优先走 host 裁音频（TLS 钉扎 + 只回传音频）。网络流的代价是按码率读视频流，所以 `_resolveSubtitleTimingAudio({limitMs})`：波形与自动对轴只抽探测上界（前 20 分钟，`subtitleTimingStreamEndMs`），语音转录抽整集；获取按「来源 + 音轨 + 截止时刻」复用、失败不缓存、退页删临时文件（与互联分支共用 `_cachedTimingAudio`）。提交 `cfeb7945f0`。
  - **审查返工**（长读与短裁不是一回事）：① 新增 `FfmpegRunControl` + 可选能力 `ControllableFfmpegBackend`（桌面 CLI / ffmpeg-kit / 蓝光包装层实现，二十多个测试假件不动）：可叫停，按「无进展」判超时（ffmpeg 进度输出 / kit 日志统计回调沉默 60 秒），壁钟只作兜底；本集共用一个控制面，远端换集与退页 `_discardRemoteTimingAudio` 叫停并换新。② 中继 `longRead`：保留 HLS 分片预取、master 选最低码率档（`selectHlsMasterVariant(lowest:)`）。③ googlevideo audio-only 流复用制卡的 range 物化（取消时关闭下载客户端）。④ Jellyfin / Emby 转码会话不给对轴读（从第 0 片读会让服务器为两边来回重启转码）：新能力 `RemoteVideoTimingAudioSource`，转码时对轴改读不挂会话的原文件直出（与「下载到本机」同一 URL），直出播放不另给。⑤ 远端分支入口要求时长已知（直播流不挂入口）。⑥ 本集已抽整集时，带上界的请求复用它。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_subtitle_timing_stream_audio_test.dart`：纯函数 `subtitleTimingStreamSource` / `subtitleTimingStreamEndMs`；端到端（真捆绑 ffmpeg-min + 真本机中继 + 自签 https 的 Emby 形状原点）抽出音轨并画出波形包络；源码守卫钉住入口判据、分支顺序、与制卡同路取流、上界传参。BUG-2692 的端到端环境抽成共享 `fushi/test/helpers/emby_relay_rig.dart`。返工补：`fushi/test/media/video/ffmpeg_run_control_test.dart`（真捆绑 ffmpeg 读「只发头不给字节」的原点：无进展判失败 / 叫停立即杀）、`ffmpeg_kit_session_timeout_test.dart` 的控制面组、`ffmpeg_relay_route_e2e_test.dart` 的长读段（只读最低档、不关预取）、`hls_relay_normalizer_test.dart` 的 lowest、`jellyfin_playback_negotiation_test.dart` 的转码对轴地址。
- **备注**：跑这两条端到端用例时**不能**设 `NO_PROXY=127.0.0.1`——ffmpeg 会忽略显式 `-http_proxy`，表现为 `Error opening input files: End of file` 且原点零请求（假红）。真机（Emby 实服）未复测，尤其转码会话下改读原文件直出这条：它会以原始码率读、绕过画质预设的码率上限（只在用户主动点对轴时发生，波形最多读 20 分钟）。Plex v1 只直放、没有转码会话，未实现该能力。
